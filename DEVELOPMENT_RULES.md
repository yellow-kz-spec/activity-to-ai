# Development Rules

1. Основной продуктовый сценарий: Android Share Sheet → source adapter → Markdown file.
2. Garmin — текущий рабочий источник без OAuth; его путь должен оставаться стабильной базой.
3. Strava использует OAuth + API; анонимную share page или share-card image нельзя считать источником полных данных.
4. Получение данных источника должно быть отделено от нормализации и Markdown-экспорта.
5. Общая модель не должна уничтожать полезные source-specific метрики.
6. Не просить пользователя вручную копировать URL или выбирать вид тренировки в нормальном сценарии.
7. Не воспроизводить карты и интерфейсы фитнес-платформ; не использовать OCR для получения графиков.
8. Не включать точные координаты в Markdown без явной продуктовой причины.
9. Исправлять источник проблемы, не добавлять зависимости без необходимости, делать изменения небольшими и проверяемыми.
10. Проверки должны соответствовать затронутому источнику: прием intent, валидный/невалидный вход, ошибки сети, сохранение, повторное разрешение папки и сообщение пользователю.
11. Изменения Garmin должны проходить существующие тесты экспортера; изменения Strava — не ухудшать Garmin baseline.
12. Обновлять `CHANGELOG.md` после завершенной задачи.

Переименование package/applicationId, legacy storage paths и OAuth callback identifiers выполняется отдельной миграцией, а не попутно с продуктовой документацией.
