# Testing

## Главный тестировщик

Almat — автор проекта и главный тестировщик MVP.

## Подход

Текущий рабочий Garmin baseline тестируется на реальных тренировках Garmin. По мере реализации Strava для него нужен отдельный набор OAuth, share-intent, API и export тестов без ослабления Garmin regression coverage.

Исправление ошибок основного сценария имеет более высокий приоритет, чем новые функции.

## Минимальные тесты

### Garmin regression baseline

- первая отправка ссылки и выбор папки;
- повторная отправка без повторного выбора папки;
- беговая тренировка;
- велосипедная тренировка;
- тренировка с мощностью;
- тренировка без мощности;
- тренировка с кругами;
- тренировка без части расширенных показателей;
- неверная ссылка;
- недоступная публичная страница;
- отсутствие интернета;
- ошибка записи в папку;
- два экспорта с одинаковой датой и названием.

### Strava near-term coverage

- первое OAuth-подключение, отмена и отказ в обязательном scope;
- сохранение состояния подключения после перезапуска;
- обновление истекшего access token и безопасная обработка отозванного refresh token;
- локальное отключение без раскрытия токенов;
- прием `ACTION_SEND` `image/*` с URL в `EXTRA_TEXT`;
- определение активности, API retrieval и Markdown export после их реализации;
- проверка, что Strava-изменения не меняют Garmin export baseline.

## Критерий готовности MVP

MVP считается пригодным для следующего этапа после успешной обработки не менее 10 реальных тренировок без ручного вмешательства в данные.

Этот критерий относится к текущему Garmin baseline и сам по себе не означает готовность Strava export или общей adapter architecture.
